### 1. تشريح الفروق الجوهرية بين المآخذ الخام ومآخذ النظام القياسية (Raw Sockets vs. Berkeley Sockets)
تعد مسألة الصلاحيات في Nmap من أدق المسائل التقنية التي يغفل عنها الكثير من المبتدئين:
* **المآخذ الخام (Raw Sockets - `SOCK_RAW`):**
  * تتطلب صلاحيات جذرية (`CAP_NET_RAW` في لينكس أو حساب `root` / `Administrator`).
  * تسمح لـ Nmap ببناء ترويسة IP وترويسة TCP/UDP/ICMP بايت ببايت، وتعيين حقول مثل `Sequence Number`, `Acknowledgment Number`, `Window Size`, وقيم الرايات (Flags: SYN, ACK, FIN, RST, URG, PSH) بحرية تامة دون تدخل من مكدس الشبكة في نواة نظام التشغيل.
* **المآخذ القياسية (Berkeley Sockets - `SOCK_STREAM`):**
  * متاحة لأي مستخدم عادي غير متميز.
  * لا تملك وصولاً لصياغة الترويسات؛ بل تستدعي دوال النواة الجاهزة مثل `connect(sockfd, &addr, sizeof(addr))`.
  * تقوم النواة تلقائياً بالتحكم في المصافحة الثلاثية (Three-Way Handshake) وإرسال حزمة `SYN` مع رقم تسلسلي تفرضه النواة.
  * **النتيجة المترتبة في فحص `-PA` (TCP ACK Ping):** عندما يطلب مستخدم عادي تنفيذ `-PA`، تعجز مكتبة Nmap عن صياغة حزمة `ACK` يتيمة عبر دالة `connect()`، فيتحول Nmap صامتاً إلى استدعاء `connect()` الذي يُخرج حزمة `SYN`، مما يفقد الفحص خاصيته الأساسية إذا لم يتوفر تصريح `sudo`.

### 2. ميكانيكية استجابة مكدس بروتوكول TCP للاتصالات غير المتوقعة (RFC 793 Reset Dynamics)
وفقاً للمعيار القياسي RFC 793 (Section 3.4):
* **الحالة الأولى (منفذ مغلق واستقبال حزمة SYN):**
  * إذا استلم نظام تشغيل حزمة `SYN` موجهة لمنفذ غير مفتوح (لا يوجد تطبيق يستمع إليه)، يجب على النظام إرجاع حزمة `RST, ACK`.
* **الحالة الثانية (استقبال حزمة ACK لاتصال غير معروف):**
  * إذا استلم نظام تشغيل حزمة `ACK` تحمل رقماً تأكيدياً لاتصال لم يسبق إنشاؤه في جدول حالات النواة (Connection Table)، تنص القاعدة على:
    > "If the connection does not exist (CLOSED) then a reset is sent in response to any incoming segment except another reset. In particular, segments containing acknowledgments for nonexistent connections are answered with a reset."
  * يرسل النظام حزمة `RST` تملك رقم تسلسلي مطابق لرقم الـ ACK المستلم.
  * هذا السلوك هو الأساس الرياضي الذي يجعل فحص **TCP ACK Ping (`-PA`)** قادراً على كشف الأجهزة الحية خلف الجدران النارية غير المعتمدة على الحالة (Stateless Firewalls)، حيث يسمح الجدار الناري لحزمة الـ ACK بالمرور ظناً منه أنها جزء من محادثة سابقة، فيرد الهدف بـ `RST`، مما يُعلم المختبر بأن الهدف حي ويعمل.

### 3. مصفوفة رسائل ICMP الاستعلامية (RFC 792 Reference Table)

```text
+-------------------+------+------+---------------------------------------------+
|    Message Type   | Type | Code |             الوظيفة التكتيكية في الفحص        |
+-------------------+------+------+---------------------------------------------+
| Echo Request      |  8   |  0   | الفحص القياسي (Ping) - الأكثر عرضة للحجب     |
| Echo Reply        |  0   |  0   | تأكيد نشاط الجهاز رداً على Type 8            |
| Destination Unr.  |  3   | 1-15 | Code 3 (Port Unreachable) يؤكد نشاط الهدف   |
| Time Exceeded     |  11  |  0   | انتهاء TTL - تستخدمها أداة Traceroute        |
| Timestamp Request |  13  |  0   | طلب توقيت النظام - يتجاوز حجب Type 8         |
| Timestamp Reply   |  14  |  0   | إرجاع التوقيت بالمللي ثانية رداً على Type 13 |
| Address Mask Req. |  17  |  0   | طلب قناع الشبكة الفرعية                     |
| Address Mask Rep. |  18  |  0   | إرجاع قناع الشبكة رداً على Type 17           |
+-------------------+------+------+---------------------------------------------+
```

### 4. تحليل حسابات الشبكات الفرعية (CIDR Block Expansion Logic)
في لغة البرمجة C++ الخاصة بأداة Nmap (تحديداً في ملف `TargetGroup.cc`):
* عندما تُعطى Nmap هدفاً بصيغة CIDR مثل `10.10.12.13/29`:
  1. يقوم Nmap بحساب قناع الشبكة (Netmask): `/29` يقابل `255.255.255.248` ثنائياً (`11111111.11111111.11111111.11111000`).
  2. يقوم بإجراء عملية `Bitwise AND` بين عنوان الـ IP والقناع:
     $$\text{Network ID} = 10.10.12.13 \text{ AND } 255.255.255.248 = 10.10.12.8$$
  3. يقوم بإنشاء حلقة تكرارية تبدأ من `10.10.12.8` وتستمر بعدد $2^{(32 - 29)} = 8$ عناوين حتى تصل إلى `10.10.12.15`.
  4. لذلك يبدأ الفحص دائماً بعنوان الشبكة `10.10.12.8`.

### 5. توجيهات الأداء الميداني لتسريع استكشاف الأجهزة (Performance Tuning)
عند فحص نطاقات ضخمة (مثل شبكة فئة B تضم 65,536 جهازاً)، يوصى بدمج المعاملات التالية:
```bash
# فحص استكشافي فائق السرعة لنطاق ضخم
sudo nmap -sn -PE -PS22,80,443 -n --min-rate 1000 --max-retries 1 10.10.0.0/16 -oG live-hosts.gnmap
```
* `--min-rate 1000`: يفرض إرسال ما لا يقل عن 1,000 حزمة في الثانية لمنع التباطؤ.
* `--max-retries 1`: تقليل عدد المحاولات لتجاوز العناوين الصامتة سريعاً.
* `-n`: إلغاء استعلامات الـ DNS تماماً لتفادي اختناق خوادم الأسماء.
* `-oG`: تصدير المخرجات بصيغة Greppable لسهولة تصفية الأجهزة بـ `awk` أو `grep`.
