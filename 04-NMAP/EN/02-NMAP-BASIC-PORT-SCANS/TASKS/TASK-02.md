# المهمة 02: منافذ بروتوكولات TCP و UDP وحالات Nmap الست (Task 02: TCP and UDP Ports)

---

### 1. الوصف العام (Stage A: Original Task Overview)
تستعرض هذه المهمة المفاهيم الأساسية للمنافذ الشبكية لبروتوكولي **TCP (Transmission Control Protocol)** و **UDP (User Datagram Protocol)**، وتوزيع المنافذ الافتراضية للخدمات الشائعة، بالإضافة إلى التصنيف المعياري لـ **حالات المنافذ الست في Nmap (The Six Port States)**.

---

### 2. التفكير التحليلي المستقل (Stage B: Independent Analytical Thinking)

#### تحليل الخدمات والمنافذ الافتراضية:
* **منفذ UDP 53:** مخصص لنظام أسماء النطاقات **DNS (Domain Name System)**؛ حيث تعتمد استعلامات ترجمة العناوين الاعتيادية على سرعة UDP وخفة وزنه.
* **منفذ TCP 22:** مخصص لبروتوكول الإدارة الآمنة عن بعد **SSH (Secure Shell)**، والذي يعتمد على TCP لضمان تسليم حزم الأوامر والبيانات المشفرة دون فقدان.

#### تشريح حالات المنافذ الست المعترف بها في Nmap:
لا يكتفي Nmap بتصنيف المنافذ إلى "مفتوح" أو "مغلق"؛ بل يمتلك نظام تصنيف دقيق يتكون من **6 حالات (Six States)** تعكس سلوك الجدران النارية والأنظمة:
1. **`Open` (مفتوح):** يوجد تطبيق يستمع بفاعلية للمنفذ وجاهز لقبول الاتصالات (Accepting connections).
2. **`Closed` (مغلق):** المنفذ يمكن الوصول إليه ويستجيب لحزم الفحص (مثل إرجاع حزمة `RST` في TCP أو خطأ `ICMP Type 3 Code 3` في UDP)، ولكن لا يوجد تطبيق يستمع إليه في النواة.
3. **`Filtered` (مفلتر / محجوب):** يعجز Nmap عن معرفة ما إذا كان المنفذ مفتوحاً أم مغلقاً لأن جداراً نارياً (Firewall) أو جهاز تصفية حزم أسقط الحزمة الاستعلامية (Dropped) أو منع الرد من الوصول.
4. **`Unfiltered` (غير مفلتر):** يعني أن المنفذ يمكن الوصول إليه واستجاب لحزم الفحص (مثل فحص ACK Scan بإرجاع RST)، لكن Nmap لا يستطيع الجزم هل هو مفتوح أم مغلق.
5. **`Open|Filtered` (مفتوح أو مفلتر):** يظهر عندما لا ينتج عن المنفذ أي رد مطلقاً في الفحوصات التي تتوقع الصمت عند الفتح (مثل فحوصات UDP و Null و FIN و Xmas)؛ فالصمت قد يعني أن المنفذ مفتوح ويتجاهل الحزمة الشاذة، أو أن جدار الحماية أسقط الحزمة.
6. **`Closed|Filtered` (مغلق أو مفلتر):** حالة نادرة تظهر في فحص الخمول (IP ID Idle Scan) عندما يتعذر التمييز بين الإغلاق والحجب.

* **ما هي الحالة الأكثر أهمية لمختبر الاختراق؟**
  * الحالة الأكثر أهمية وجاذبية هي **`Open`**؛ لأن المنفذ المفتوح يمثل خدمة حقيقية تعمل على النظام (مثل خادم ويب، خادم قاعدة بيانات، خادم ملفات) يمكن للمختبر استخراج إصداراتها، والبحث عن ثغرات في برمجياتها، واستغلالها للوصول إلى النظام.

### 3. التلميحات الموجهة (Stage C: Guided Hints)
* تذكر البروتوكول المسؤول عن ترجمة أسماء المواقع (`google.com`) إلى عناوين IP ويعمل افتراضياً على منفذ UDP 53.
* فكر في أداة الاتصال الطرفي الآمنة بالخوادم التي تستخدم المنفذ 22.
* راجع قائمة الحالات الست المذكورة في نص المهمة وفي توثيق Nmap الرسمي.

---

### 4. الحل العملي المفصل (Stage D: Complete Practical Solution)
التحقق من تعيينات المنافذ القياسية في ملف الخدمات المحلي في نظام لينكس:
```bash
# استخراج خدمة منفذ 53 UDP
grep -w "53/udp" /etc/services
# الناتج: domain 53/udp (DNS)

# استخراج خدمة منفذ 22 TCP
grep -w "22/tcp" /etc/services
# الناتج: ssh 22/tcp
```

### 5. الإجابات النموذجية المعتمدة (Stage E: Final Answers)
1. **السؤال 1:** Which service uses UDP port 53 by default?
   * **الإجابة:** `DNS`
2. **السؤال 2:** Which service uses TCP port 22 by default?
   * **الإجابة:** `SSH`
3. **السؤال 3:** How many port states does Nmap consider?
   * **الإجابة:** `6`
4. **السؤال 4:** Which port state is the most interesting to discover as a pentester?
   * **الإجابة:** `Open`

### 7. المخرجات التعليمية والدروس المستفادة (Stage G: Educational Takeaway)
* التمييز بين `Filtered` و `Closed` حاسم لفهم معمارية أمان الهدف؛ فالمنفذ `Closed` يخبرك بأن الحزمة وصلت للنواة ولا يوجد جدار ناري يعترضها، بينما `Filtered` يكشف وجود جدار حماية (Firewall) يعترض تدفق البيانات.
