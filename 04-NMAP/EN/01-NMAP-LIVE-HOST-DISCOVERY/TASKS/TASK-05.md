# المهمة 05: اكتشاف الأجهزة عبر بروتوكول ARP في Nmap (Task 05: Nmap Host Discovery Using ARP)

---

### 1. الوصف العام (Stage A: Original Task Overview)
تركز هذه المهمة على استكشاف الأجهزة الحية داخل نفس الشبكة المحلية (Ethernet / Same Subnet) باستخدام بروتوكول استبانة العناوين **ARP (Address Resolution Protocol)**.

عند تشغيل أداة Nmap بحساب ذي صلاحيات مميزة (`root` أو `sudo`) على شبكة إيثرنت محلية، فإن Nmap يمتلك سلوكاً افتراضياً خاصاً: **يتجاهل كافة طلبات ICMP أو TCP/UDP pings ويتحول تلقائياً إلى إرسال طلبات ARP Requests** (ما لم يتم فرض خيارات أخرى)، أو يمكن تخصيص ذلك صراحة عبر المعامل:
```bash
sudo nmap -PR -sn TARGET_SUBNET
```
حيث:
* `-PR`: يفرض استخدام ARP Ping.
* `-sn`: يُعطّل فحص المنافذ (No Port Scan) ويكتفي فقط باكتشاف الأجهزة الحية (Host Discovery Only).

---

### 2. التفكير التحليلي المستقل (Stage B: Independent Analytical Thinking)
* **لماذا يعتبر فحص ARP هو الأفضل والأكثر موثوقية على الشبكة المحلية؟**
  1. **عدم إمكانية حجبه بواسطة الجدران النارية الشخصية (Firewall Immune):**
     * إذا قام مستخدم بتفعيل جدار ناري شخصي (مثل Windows Defender Firewall) لحجب رسائل ICMP Echo (Ping) أو حجب كافة منافذ TCP، فلن يتمكن إطلاقاً من حجب رسائل ARP.
     * السبب: إذا تجاهل نظام التشغيل طلبات ARP، فلن يستطيع كارت الشبكة التخاطب مع أي جهاز آخر على الشبكة المحلية، وستنقطع عنه الشبكة كلياً.
  2. **السرعة الفائقة والفعالية (Low Latency & High Speed):**
     * معالجة ARP تتم على مستوى كارت الشبكة والنواة مباشرة (Layer 2) دون الحاجة للوصول إلى طبقات التطبيقات العليا، مما يجعل فحص شبكة كاملة `/24` (256 جهازاً) يستغرق أقل من ثانية واحدة.
* **النتيجة المعملية:** عند فحص شبكة الضحية المعملية `CONNECTION_IP/24` عبر واجهة الـ VPN أو AttackBox، يتم اكتشاف جهاز واحد فقط نشط يستجيب لطلب الـ ARP (`1`).

---

### 3. التلميحات الموجهة (Stage C: Guided Hints)
* نفّذ أمر الفحص باستخدام صلاحيات `sudo` للتأكد من قدرة Nmap على إنشاء واستقبال حزم الإيثرنت الخام (Raw Ethernet Frames).
* الصيغة القياسية: `sudo nmap -PR -sn <TARGET_IP>/24`.

---

### 4. الحل العملي المفصل (Stage D: Complete Practical Solution)
تنفيذ الفحص المباشر على شبكة الهدف عبر محطة كالي أو AttackBox:
```bash
# تنفيذ فحص ARP لاكتشاف الأجهزة الحية في الشبكة الفرعية
sudo nmap -PR -sn 10.10.210.0/24

# مخرجات الفحص النموذجية:
# Starting Nmap 7.9X ( https://nmap.org )
# Nmap scan report for 10.10.210.100
# Host is up (0.00034s latency).
# MAC Address: 02:42:0A:0A:D2:64 (Unknown)
# Nmap done: 256 IP addresses (1 host up) scanned in 1.42 seconds
```
يُظهر التقرير أن هناك جهازاً واحداً فقط نشطاً على الشبكة الفرعية المستهدفة (`1 host up`).

### 7. المخرجات التعليمية والدروس المستفادة (Stage G: Educational Takeaway)
* **القيد الجغرافي لفحص ARP:** تذكر دائماً أن فحص ARP فعال فقط عندما تكون في نفس مجال البث (Layer 2 Broadcast Domain) للهدف. إذا كنت تفحص شبكة عبر راوتر أو عبر الإنترنت، فلن تستطيع استخدام `-PR` ويجب الانتقال إلى فحص بروتوكولات الطبقة الثالثة والرابعة (ICMP / TCP / UDP).
