# المهمة 07: اكتشاف الأجهزة عبر بروتوكولات TCP و UDP في Nmap (Task 07: Nmap Host Discovery Using TCP and UDP)

---

### 1. الوصف العام (Stage A: Original Task Overview)
تتناول هذه المهمة استكشاف الأجهزة الحية على مستوى طبقة النقل (Transport Layer - Layer 4) باستخدام بروتوكولات **TCP** و **UDP**.

تعتبر هذه التقنية ذات أهمية قصوى في بيئات الإنترنت والشبكات المحمية، حيث تقوم معظم الجدران النارية الحديثة بحجب كافة رسائل بروتوكول ICMP (سواء كانت Echo أو Timestamp أو غيرها). في المقابل، تضطر الجدران النارية والأنظمة للسماح لحزم TCP أو UDP بالمرور للوصول إلى الخدمات العامة (مثل خوادم الويب HTTP/HTTPS أو خوادم البريد أو خوادم الأسماء DNS).

تتيح Nmap الخيارات التكتيكية التالية:
1. **TCP SYN Ping (`-PS[port_list]`):** إرسال حزم تحمل راية `SYN`. (المنفذ الافتراضي هو 80).
2. **TCP ACK Ping (`-PA[port_list]`):** إرسال حزم تحمل راية `ACK`. (المنفذ الافتراضي هو 80).
3. **UDP Ping (`-PU[port_list]`):** إرسال حزم UDP فارغة إلى منافذ مغلقة غالباً (الافتراضي 40,125).

### 2. التفكير التحليلي المستقل (Stage B: Independent Analytical Thinking)

#### تشريح سلوك الصلاحيات المتميزة مقابل غير المتميزة (Privileged vs Unprivileged Sockets):
* **لماذا تتصرف Nmap بشكل مختلف وفقاً لصلاحيات المستخدم؟**
  * المستخدم ذو الصلاحيات المرتفعة (`root` / `sudo`) يمتلك القدرة على فتح **مآخذ خام (Raw Sockets)** في نواة النظام. تتيح المآخذ الخام للمختبر صياغة وتحديد كل راية (Flag) وكل حقل في ترويسة حزمة TCP يدوياً.
  * المستخدم العادي (Unprivileged User) محروم أمنياً من فتح المآخذ الخام، ومقيد فقط باستدعاءات النظام القياسية مثل `connect()`.

* **تحليل فحص TCP SYN Ping (`-PS`):**
  * **بحساب Root:** يرسل Nmap حزمة `SYN` مصاغة يدوياً. إذا استجاب الهدف بـ `SYN/ACK` (المنفذ مفتوح) أو بـ `RST` (المنفذ مغلق)، يعلم Nmap يقيناً أن الجهاز نشط (Host is up).
  * **بحساب عادي (Non-root):** يستدعي Nmap دالة `connect()` في نظام التشغيل. ماذا تفعل دالة `connect()` لبدء الاتصال بموجب معيار RFC 793؟ ترسل حزمة تحمل راية **`SYN`**!
  * **النتيجة:** فحص `TCP SYN Ping` **يحافظ على إرسال نوع الحزمة التي سُمي بها (حزمة SYN)** حتى لو نُفذ بحساب مستخدم عادي غير متميز.

* **تحليل فحص TCP ACK Ping (`-PA`):**
  * **الفكرة التكتيكية:** إرسال حزمة تحمل راية `ACK` وحدها دون تأسيس اتصال مسبق. وفقاً لقواعد RFC 793، فإن أي مكدس TCP يستلم حزمة ACK مفاجئة لاتصال غير موجود لديه، يجب أن يرد فوراً بحزمة `RST` (Reset)، مما يثبت نشاط الجهاز ويخترق الجدران النارية البسيطة غير المعتمدة على الحالة (Stateless Firewalls).
  * **معضلة الصلاحيات:** لا يوجد في نظام التشغيل أي استدعاء نظام قياسي يسمح لمستخدم عادي بإرسال حزمة TCP ACK مجردة في الهواء دون اتصال قائم. الطريقة الوحيدة لصياغة حزمة ACK يتيمة هي عبر الـ Raw Sockets.
  * إذا حاول مستخدم عادي تشغيل `-PA`، يفشل Nmap في صياغة الـ ACK الخام ويتحول قسراً إلى استخدام دالة `connect()` (التي ترسل SYN بدلاً من ACK).
  * **النتيجة:** فحص `TCP ACK Ping` **يتطلب حصرياً صلاحيات مميزة (`root`) لكي يرسل حزمة ACK حقيقية كما سُمي بها**.

* **تخصيص المنافذ المستهدفة في فحص SYN:**
  * إذا أردنا فحص خدمة معينة مثل Telnet (المنفذ 23)، نضيف رقم المنفذ مباشرة بعد الخيار: **`-PS23`**.

### 3. التلميحات الموجهة (Stage C: Guided Hints)
* تذكر دائماً: بروتوكول TCP يبدأ الاتصال بحزمة SYN، ودالة `connect()` ترسل SYN تلقائياً دون الحاجة لصلاحيات الـ Root.
* لتحديد منافذ متعددة في خيار SYN Ping، اكتب أرقام المنافذ مفصولة بفواصل: `-PS21,22,23,80`.

---

### 4. الحل العملي المفصل (Stage D: Complete Practical Solution)

#### أمثلة الأوامر الميدانية:
```bash
# تنفيذ TCP SYN Ping على منفذ Telnet (23) بصلاحيات root
sudo nmap -PS23 -sn 10.10.210.100

# تنفيذ TCP ACK Ping لاختراق الجدران النارية غير المعتمدة على الحالة
sudo nmap -PA80 -sn 10.10.210.100

# تنفيذ UDP Ping لاستكشاف الأجهزة عبر منافذ UDP المغلقة
sudo nmap -PU -sn 10.10.210.100
```

#### تحليل استجابة UDP Ping:
* يرسل Nmap حزمة UDP إلى منفذ عشوائي مغلق على الهدف.
* إذا كان الهدف حياً والمنفذ مغلقاً، يُجبر نظام الهدف على إرسال رسالة خطأ ICMP:
  `ICMP Destination Unreachable (Port unreachable - Type 3, Code 3)`
* بمجرد استلام Nmap لرسالة الخطأ هذه، يتأكد أن الهدف نشط (Host is up).

### 5. الإجابات النموذجية المعتمدة (Stage E: Final Answers)
1. **السؤال 1:** Which TCP ping scan still sends the packet type it is named after when run from an unprivileged account?
   * **الإجابة:** `TCP SYN Ping`
2. **السؤال 2:** Which TCP ping scan needs a privileged account to send the packet type it is named after?
   * **الإجابة:** `TCP ACK Ping`
3. **السؤال 3:** What option do you need to add to Nmap to run a TCP SYN ping scan on the telnet port?
   * **الإجابة:** `-PS23`
