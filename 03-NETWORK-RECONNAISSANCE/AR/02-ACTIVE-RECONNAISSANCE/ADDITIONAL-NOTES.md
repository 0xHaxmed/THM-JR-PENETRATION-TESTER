# Additional Technical Notes: Active Reconnaissance
## ملاحظات تقنية متقدمة: الاستطلاع النشط وتحليل الحزم

---

## 1. التشريح الشبكي المعمق لبروتوكول ICMP (RFC 792)
بروتوكول رسائل التحكم في الإنترنت (**Internet Control Message Protocol**) يعمل في الطبقة الثالثة (Network Layer)، ولكنه يُغلّف مباشرة داخل حزمة IP (IP Protocol 1) دون استخدام ترويسة TCP أو UDP.

```text
+-----------------------+-----------------------+-----------------------+
|  IPv4 Header (20 B)   |   ICMP Header (8 B)   |  Payload (Variable)   |
+-----------------------+-----------------------+-----------------------+
```

### حقول ترويسة ICMP بالتفصيل:
1. **Type (8 bits):** يحدد الغرض الأساسي للرسالة:
   * `Type 8`: Echo Request (طلب الصدى الصادر عن أمر Ping).
   * `Type 0`: Echo Reply (رد الصدى الوارد من الهدف الحي).
   * `Type 3`: Destination Unreachable (الهدف أو المنفذ غير متاح).
   * `Type 11`: Time Exceeded (انتهاء صلاحية الـ TTL أثناء الانتقال، أساس عمل Traceroute).
2. **Code (8 bits):** تفصيل فرعي لنوع الرسالة (مثلاً في Type 3: Code 1 يعني Host Unreachable، و Code 3 يعني Port Unreachable).
3. **Checksum (16 bits):** المجموع الاختباري المعتمد على خوارزمية 1's complement لاكتشاف أي تلف في الحزمة أثناء البث.
4. **Header Data (32 bits):** تختلف باختلاف النوع؛ ففي Echo Request تتضمن `Identifier (16 bits)` و `Sequence Number (16 bits)` لمزامنة كل رد بالطلب المطابق له.

## 2. آليات التتبع: Linux Traceroute مقابل Windows Tracert
يوجد اختلاف هندسي جوهري بين تطبيق أداة التتبع في أنظمة Linux وأنظمة Windows:

| المعيار | Linux `traceroute` | Windows `tracert` |
|---|---|---|
| **البروتوكول الافتراضي** | حزم **UDP** على منافذ عشوائية عالية (33434+) | حزم **ICMP Echo Request** (Type 8) |
| **سلوك المنفذ عند الوصول للهدف** | يستقبل الهدف حزمة UDP على منفذ مغلق فيرد بـ `ICMP Type 3 Code 3 (Port Unreachable)` | يستقبل الهدف حزمة ICMP فيرد بـ `ICMP Type 0 (Echo Reply)` |
| **تجاوز الجدران النارية** | خيار `-I` لاستخدام ICMP بدلاً من UDP، أو خيار `-T` لاستخدام TCP SYN على المنفذ 80 | يعتمد على ICMP فقط، لذا يفشل غالباً إذا حظر الجدار الناري الـ ICMP |

## 3. استخراج الترويسات الصامت (Silent Banner Grabbing)
عند الاتصال بمقابس الويب أو الخدمات النصية، غالباً ما تسجل الخوادم طلبات الاتصال. للحفاظ على الهدوء وتفادي إغراق السجلات (Log Flooding):
1. **استخدام HTTP HEAD بدلاً من GET:**
   * يطلب الأمر `HEAD / HTTP/1.1` الترويسات فقط دون تحميل جسم الصفحة، مما يقلل البايتات المرسلة ويكشف إصدار الخادم بسرعة:
     ```http
     HEAD / HTTP/1.1
     Host: target.thm

     ```
2. **استخدام Netcat مع مهلة زمنية (Timeout):**
   * عند الاتصال بخدمات تستمع ولا ترسل رايات ترحيبية فورية، استخدم الخيار `-w`:
     ```bash
     nc -v -w 3 target.thm 80
     ```

## 4. قيود الاستطلاع النشط وجدران الحماية (OPSEC Considerations)
* **انكشاف العنوان الحقيقي للفاحص:** في الاستطلاع النشط، يتصل عنوان IP الخاص بمختبر الاختراق بالهدف مباشرة. لا يمكن استخدام تزييف العناوين (IP Spoofing) في اتصالات TCP الكاملة لأن المصافحة الثلاثية (SYN-ACK) لن تعود إلى جهاز المختبر.
* **الحلول التكتيكية للمختبر المعتمد:**
  * استخدام خوادم بروكسي آمنة أو VPN معتمد متفق عليه مسبقاً في قواعد الاشتباك (RoE).
  * توثيق عنوان IP المصدر الخاص بالمختبر رسمياً لدى الـ SOC لتجنب البلاغات الكاذبة لدى مزودي الخدمة (ISPs).
