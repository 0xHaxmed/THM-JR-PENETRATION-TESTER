### 1. المعمارية الأمنية لمحركات المتصفحات وفارق شجرة الـ DOM عن كود المصدر
* **المسار المعماري لبناء الصفحة (Critical Rendering Path):**
  $$\text{HTML Bytes} \xrightarrow{\text{Tokens}} \text{Nodes} \xrightarrow{\text{DOM Tree}} + \text{CSSOM Tree} \xrightarrow{\text{Render Tree}} \xrightarrow{\text{Layout}} \xrightarrow{\text{Paint}}$$
* **الفارق الجوهري بين "View Source" و "DOM Inspector":**
  * **عرض المصدر (View Source):** يعرض حزم بيانات الـ HTML الخام كما خرجت من مقبس خادم الويب (Over-the-wire). في تطبيقات الواجهة الأحادية الحديثة (React, Vue, Angular)، يظهر كود المصدر غالباً كصفحة فارغة تحتوي فقط على:
    `<div id="root"></div><script src="bundle.js"></script>`
  * **فاحص العناصر (DOM Inspector):** يعرض شجرة كائنات المستند الحية بعد أن قام محرك الجافاسكربت (مثل V8 في كروم أو SpiderMonkey في فايرفوكس) بمعالجة ملفات الجافاسكربت وبناء المكونات وحقن البيانات ديناميكياً.
  * **الأثر الأمني:** لا يمكن تقييم تطبيقات الويب الحديثة بالاعتماد على View Source وحده؛ بل يجب استخدام الـ Inspector لفحص العناصر المولدة برمجياً في الذاكرة.

### 2. تسريب الأكواد الأصلية عبر خرائط المصدر (JavaScript Source Maps Exploitation)
* في خطوط الإنتاج البرمجية الحديثة (CI/CD Pipelines)، يقوم المطورون بكتابة كود الـ TypeScript أو ES6 المتقدم، ثم يتم تجميعه وضغطه (Minified & Bundled) عبر أدوات مثل Webpack أو Vite في ملفات مثل `main.min.js`.
* لتسهيل تصحيح الأخطاء، تنشئ تلك الأدوات ملفات تسمى **خرائط المصدر (Source Maps - `.js.map`)** مثل `main.min.js.map`.
* **الثغرة الشائعة:** رفع ملفات الـ `.map` إلى خوادم الإنتاج العامة.
* **الاستغلال:** عند فتح تبويب Debugger / Sources، يقوم المتصفح تلقائياً بتحميل ملف الـ `.map` وإعادة بناء الكود المصدري الأصلي غير المضغوط للمشروع كاملاً، بما فيه المجلدات الداخلية، والتعليقات الخاصة، وأسماء المتغيرات الصريحة، ونماذج قواعد البيانات، ومفاتيح الـ API السرية!

### 3. التشريح المعياري لرايات أمان ملفات تعريف الارتباط (RFC 6265bis Cookie Security Flags)

```text
+----------------+---------------------+---------------------------------------------------------------+
|     الراية     |    القيم الممكنة    |                     الوظيفة الأمنية التكتيكية                 |
+----------------+---------------------+---------------------------------------------------------------+
| HttpOnly       | Flag Present (True) | يمنع دوال الجافاسكربت (document.cookie) من قراءة الكوكي.       |
|                | Flag Absent (False) | يحمي جلسات المصادقة من السرقة عند وجود ثغرات XSS.            |
|----------------+---------------------+---------------------------------------------------------------+
| Secure         | Flag Present (True) | يمنع المتصفح من إرسال الكوكي عبر اتصالات HTTP غير المشفرة.    |
|                | Flag Absent (False) | يحمي من التنصت السلبي على الشبكة (Man-in-the-Middle).         |
|----------------+---------------------+---------------------------------------------------------------+
| SameSite       | Strict              | لا يُرسل الكوكي إطلاقاً مع أي طلب عابر للمواقع (أقصى حماية). |
|                | Lax (Default)       | يُرسل فقط مع طلبات التنقل الآمنة (مثل النقر على رابط GET).    |
|                | None                | يُرسل مع كافة الطلبات العابرة للمواقع (يتطلب راية Secure).    |
+----------------+---------------------+---------------------------------------------------------------+
```

### 4. المخاطر الأمنية لاستعراض المجلدات (Directory Indexing Vulnerabilities)
* **سبب الخلل المعماري:**
  * في خادم **Apache**: تفعيل الموديول `mod_autoindex` مع التوجيه:
    `Options +Indexes` داخل ملف `httpd.conf` أو `.htaccess`.
  * في خادم **Nginx**: وجود السطر:
    `autoindex on;` داخل كتلة `location` أو `server`.
* **الخطر الأمني الكامن:**
  * يتيح استعراض المجلدات للمهاجم فهرسة كافة الملفات المخفية دون الحاجة للتخمين.
  * يساعد في اكتشاف ملفات النسخ الاحتياطي الخطيرة (مثل `config.php.bak`, `backup.sql`, `settings.old`) التي يتركها مسؤولو النظام، أو استخراج مستودعات كود المصدر كاملة عبر مجلد `.git/` المكشوف.
