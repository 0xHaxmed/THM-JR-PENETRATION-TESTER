### 1. المقارنة الهندسية لأدوات التخمين والتعداد الآلي (Fuzzer Benchmarks: Gobuster vs ffuf vs Feroxbuster)
تتنافس عدة أدوات في سطر أوامر لينكس في مجال التخمين السريع للمسارات:
* **Gobuster (Go):** أداة متخصصة ومستقرة جداً؛ تتميز بوجود أوضاع منفصلة وواضحة (`dir`, `dns`, `vhost`, `s3`). مثالية للاختبارات القياسية والتقارير المنظمة.
* **ffuf - Fuzz Faster U Fool (Go):** أداة تخمين شمولية (Full Fuzzer) فائقة السرعة والمرونة؛ تتيح وضع كلمة `FUZZ` في أي مكان في الطلب (الرابط، الترويسات، البيانات، معلمات POST)، وتمتلك خيارات تصفية دقيقة للغاية (تصفية حسب الحجم `-fs`, عدد الكلمات `-fw`, الأكواد `-fc`).
* **Feroxbuster (Rust):** أداة متطورة مكتوبة بلغة Rust؛ تتميز بخاصية **التعداد التكراري الذكي التلقائي (Recursive Discovery)**؛ حيث تبدأ تلقائياً في فحص محتويات أي مجلد جديد تكتشفه دون تدخل يدوي، وتدعم الفحص متعدد العمليات المتوازية بسرعة رهيبة.

### 2. هندسة واختيار قواميس التخمين (Wordlist Engineering - SecLists Structure)
يمثل مستودع **SecLists** (الذي يشرف عليه الباحث الأمني Daniel Miessler) المرجع القياسي العالمي للقواميس:
* مسار القواميس في نظام كالي ولينكس: `/usr/share/wordlists/seclists/`
* **أهم القواميس في استكشاف محتوى الويب:**
  1. `Discovery/Web-Content/common.txt` (حوالي 4,700 كلمة): القاموس السريع الأفضل كخطوة أولى لكشف أهم المجلدات والملفات القياسية.
  2. `Discovery/Web-Content/directory-list-2.3-medium.txt` (حوالي 220,000 كلمة): مستخرج من فحص وتحليل ملايين المواقع الحقيقية بواسطة أداة DirBuster؛ وهو المعيار الذهبي للفحص المعمق للمجلدات.
  3. `Discovery/Web-Content/raft-medium-files.txt` و `raft-medium-directories.txt`: ممتازة لاكتشاف الملفات والمجلدات النادرة.
  4. `Discovery/DNS/subdomains-top1million-5000.txt`: لاكتشاف أشهر النطاقات الفرعية.

### 3. ميكانيكية توجيه المجالات الافتراضية عبر ترويسة المضيف (VHost Routing Mechanics)
* **المعضلة:** تمتلك الشركة خادماً واحداً بعنوان IP واحد (`192.168.1.100`) وتريد استضافة موقعها العام `acme.thm` وموقع التطوير السري `dev.acme.thm` عليه.
* **كيف يميز خادم الويب (Apache أو Nginx) الوجهة؟**
  * لا يرى نظام التوجيه على مستوى IP أي فارق (كلاهما يذهب لـ `192.168.1.100`).
  * في طبقة التطبيق (HTTP/1.1 و HTTP/2)، يفرض المعيار RFC 7230 تضمين ترويسة **`Host:`** في كل طلب.
  * يقرأ خادم الويب السطر الأول:
    ```http
    GET / HTTP/1.1
    Host: dev.acme.thm
    ```
  * يطابق الخادم قيمة `Host` مع كتل التكوين (`<VirtualHost *:80>` في Apache أو `server { server_name dev.acme.thm; }` في Nginx) ويوجه الطلب إلى مجلد موقع التطوير بدلاً من الموقع العام!
* **لماذا يفشل فحص DNS وينجح فحص VHost؟**
  * إذا لم يكن اسم `dev.acme.thm` مسجلاً في خوادم الـ DNS، فلن تستطيع أداة `gobuster dns` اكتشافه.
  * بينما تقوم أداة `gobuster vhost` بإرسال حزم HTTP إلى عنوان الـ IP الحقيقي مع استبدال ترويسة `Host:` بكلمات القاموس، مما يكشف الموقع المخفي فوراً!

### 4. بصمة أيقونة الموقع (Favicon Hashing with MurmurHash3)
* كل تطبيق ويب يمتلك أيقونة صغيرة تظهر في لسان المتصفح (`favicon.ico`).
* تقوم محركات البحث المتخصصة مثل **Shodan** و **Censys** بحساب التجزئة الرياضية للأيقونة باستخدام خوارزمية **MurmurHash3**:
  ```python
  import mmh3, requests, codecs
  response = requests.get('http://MACHINE_IP/favicon.ico')
  favicon = codecs.encode(response.content, 'base64')
  hash_val = mmh3.hash(favicon)
  print(f"http.favicon.hash:{hash_val}")
  ```
* بالبحث في محرك Shodan بهذا الهاش (`http.favicon.hash:<hash>`)، يمكن العثور على كافة خوادم الشركة والواجهات الإدارية المطابقة حول العالم حتى لو غيرت أسماء نطاقاتها!

### 5. تصاريح حاويات أمازون التخزينية (AWS S3 Permissions Exploitation)
* تصاغ روابط S3 بعدة أشكال:
  * صيغة النطاق الفرعي: `https://[bucket-name].s3.amazonaws.com`
  * صيغة المسار: `https://s3.amazonaws.com/[bucket-name]`
* **أخطاء التكوين الشائعة:**
  1. **قائمة الملفات المفتوحة (ListBucket Permission):** تتيح لأي شخص مجهول (Anonymous / All Users) استعراض أسماء كافة الملفات المخزنة في الحاوية عبر متصفح الويب أو أداة `aws-cli`:
     `aws s3 ls s3://bucket-name/ --no-sign-request`
  2. **الكتابة والرفع غير المصرح به (PutObject Permission):** تتيح للمهاجم رفع ملفات خبيثة أو تعديل أكواد الجافاسكربت المخزنة في الحاوية مما يسبب اختراقاً شاملاً للزوار (Stored XSS).
