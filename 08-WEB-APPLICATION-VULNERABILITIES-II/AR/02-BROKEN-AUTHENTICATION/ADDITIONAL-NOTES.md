## 1. الدليل الميداني المتقدم لأداة ffuf في هجمات المصادقة

تُعد أداة `ffuf` (Fuzz Faster U Fool) المعيار الميداني الأسرع لمختبري الاختراق في تنفيذ عمليات التخمين، نظراً لكتابتها بلغة Go وقدرتها على استغلال التزامن العالي (Goroutines).

### 1.1 مفاتيح وخيارات التصفية والمطابقة في ffuf
| الخيار | الوظيفة التقنية | مثال تطبيقي في المصادقة |
| :--- | :--- | :--- |
| `-w` | تحديد مسار قائمة الكلمات وتسمية المتغيرات | `-w users.txt:W1,pass.txt:W2` |
| `-X` | تحديد نوع طريقة HTTP (POST, GET, PUT) | `-X POST` |
| `-d` | تحديد جسم الطلب المشفر (POST Data) | `-d "user=FUZZ&pass=secret"` |
| `-H` | تمرير الترويسات الإضافية | `-H "Content-Type: application/x-www-form-urlencoded"` |
| `-mr` | مطابقة استجابة الخادم بناءً على تعبير نمطي (Regex) | `-mr "username already exists"` (كشف الحسابات) |
| `-fc` | حجب وتصفية رموز حالة معينة (Filter Code) | `-fc 200` (حجب محاولات الدخول الفاشلة) |
| `-fs` | حجب الاستجابات ذات الحجم المتطابق (Filter Size) | `-fs 3421` (حجب شاشات الخطأ المكررة) |
| `-t` | تحديد عدد الخيوط المتزامنة (Threads) | `-t 50` (التحكم في السرعة والـ OpSec) |
| `-p` | تحديد مهلة تأخير بين الطلبات (Delay in seconds) | `-p 0.1` (تجاوز أنظمة الكشف ومعدل الطلبات) |

### 1.2 أنماط الهجوم المزدوج (Multi-Wordlist Attack Modes)
* **Cluster Bomb Mode (الافتراضي عند استخدام أكثر من قائمة):**
  - يجرب كل كلمة في القائمة الأولى مع كل كلمة في القائمة الثانية ($N \times M$).
  - مثال: 3 مستخدمين $\times$ 100 كلمة مرور = 300 طلب.
* **Pitchfork Mode:**
  - يجرب العنصر الأول من القائمة الأولى مع العنصر الأول من القائمة الثانية بالتوازي ($N$). مفيد جداً عند اختبار أزواج حسابات مسربة مسبقاً (Combo Lists).

## 2. التشريح التقني لثغرة تلويث معلمات بروتوكول HTTP (HTTP Parameter Pollution)

تحدث ثغرة HPP عندما يتلقى التطبيق معلمات متعددة تحمل نفس الاسم، وتتعامل أطر العمل والخوادم الخلفية مع هذا التكرار بطرق مختلفة وغير قياسية:

### 2.1 سلوك خوادم الويب عند تكرار المعلمات (`?name=alice&name=bob`)
| خادم الويب / لغة البرمجة | السلوك عند التكرار | القيمة الناتجة |
| :--- | :--- | :--- |
| **PHP / Apache** | يأخذ القيمة الأخيرة فقط | `bob` |
| **ASP.NET / IIS** | يدمج القيمتين بفاصلة | `alice,bob` |
| **JSP / Apache Tomcat** | يأخذ القيمة الأولى فقط | `alice` |
| **Node.js / Express** | يحول المعلمة إلى مصفوفة (Array) | `["alice", "bob"]` |
| **Python / Flask** | يأخذ القيمة الأولى ما لم يُطلب العكس | `alice` |

### 2.2 مصفوفة `$_REQUEST` في لغة PHP
في لغة PHP، المصفوفة الفائقة `$_REQUEST` ليست كياناً مستقلاً بذاته، بل هي مصفوفة مجمعة تدمج بيانات ثلاث مصفوفات أساسية:
$$\text{\$\_REQUEST} = \text{\$\_GET} \cup \text{\$\_POST} \cup \text{\$\_COOKIE}$$
يتم تحديد أسبقية الاستبدال في ملف `php.ini` بواسطة توجيه `request_order = "GP"`.
- حرف `G` يعني Get.
- حرف `P` يعني Post.
نظراً لأن `P` تأتي بعد `G`، فإن أي معلمة بنفس الاسم قادمة في جسم طلب POST **ستكتب فوق وتستبدل** نفس المعلمة القادمة في رابط GET!
هذا الاختلاف بين استعلام الفحص (الذي قرأ من `$_GET`) واستعلام الإرسال (الذي قرأ من `$_REQUEST`) فتح الباب على مصراعيه للاستيلاء على الحساب.

## 3. العيوب الشائعة في آليات استعادة كلمات المرور (Password Reset Flaws)

1. **تسريب رمز إعادة التعيين في الاستجابة (Token Disclosure in Response):**
   - الخادم يُنشئ الرمز ويرسله في البريد، ولكنه بالخطأ يُضمن كائن الرمز في استجابة الـ JSON للعميل!
2. **حقن ترويسة المضيف (Host Header Injection in Reset Links):**
   - يعتمد السكربت على ترويسة `Host` لبناء الرابط:
     `Link: http://` + `$_SERVER['HTTP_HOST']` + `/reset?token=...`
   - يغير المهاجم الترويسة إلى `Host: attacker.thm`، فيصل الرابط للضحية موجهاً لخادم المهاجم!
3. **ضعف عشوائية الرموز (Predictable / Time-based Tokens):**
   - توليد الرمز باستخدام `md5(time())` أو معرف المستخدم، مما يتيح للمهاجم حسابه دون الحاجة لقراءة البريد.

## 4. الفرق الحاسم: الترميز مقابل التجزئة مقابل التشفير

```
[Plain Text: "password123"]
       |
       +---> Encoding (Base64)  ---> "cGFzc3dvcmQxMjM="  (Reversible by ANYONE, NO Key)
       |
       +---> Hashing (MD5)      ---> "482c811da5d5b4bc..." (One-way digest, NO Key,
       |                                                    Vulnerable to CrackStation)
       |
       +---> Encryption (AES-GCM)---> [Ciphertext + IV + Tag] (CANNOT be decrypted
                                                               without the SECRET KEY)
```

### التوقيع التشفيري للرموز (Cryptographic Signatures / HMAC)
إذا احتاج التطبيق لتخزين بيانات هوية لدى العميل، يجب عليه توقيعها تشفيرياً:
$$\text{Signature} = \text{HMAC-SHA256}(\text{Data}, \text{SecretKey})$$
عند استلام الكوكي:
1. يعيد الخادم حساب HMAC للبيانات باستخدام مفتاحه السري.
2. إذا تطابقت النتيجة مع التوقيع، يتم قبول البيانات؛ وإذا عدل العميل حرفاً واحداً (مثل تغيير `admin=false` إلى `admin=true`)، ينهار التوقيع ويرفض الخادم الطلب فوراً.
